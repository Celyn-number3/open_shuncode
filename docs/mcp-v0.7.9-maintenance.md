# 0.7.9 维护交付记录

日期：2026-10-14。范围：远程 MCP Bridge 权限控制、工程与发布规范。版本保持开发状态，不替换已发布的 0.7.8 稳定 Release。

## 已落地

- 新连接默认只读；项目补丁需本机授权；终端执行、输入、输出与自定义工具需分别获得整机会话授权。
- 本机交互确认，默认 15 分钟；权限不持久化。撤销、断开、闲置及到期恢复只读，并中止活动工具信号、请求取消管理的终端命令。
- 所有远程工具在真正执行时统一检查，覆盖并发队列和自定义工具；不允许工具参数自行提升权限；非标准别名失败关闭。
- 显式文件路径、批量读取和补丁移动目的地进行真实路径检查，覆盖目录穿越、符号链接与 Windows junction。
- 按会话过滤工具列表，禁用权限敏感工具列表的公共缓存。
- 新增状态栏与四个中文权限命令；构建信息包含版本、源码提交、输入哈希和加载路径。
- Bridge 输出、活动状态对常见密钥模式脱敏；审计不记录参数和完整输出。
- `version.json` 统一版本来源，保存经 SHA-256 固定的上游运行基线，可重复生成增量产物并检查输入哈希。
- 新增默认预览、备份、逐文件原子替换及失败回滚的同步工具；新增剔除本地文件、CRC 与 SHA-256 校验的打包工具。
- 中文 README、仓库下载与 Issues 链接指向维护仓库，保留上游署名与许可证。新增 Windows/Linux CI 配置。

5. 已在独立编辑器用户目录以源码扩展开发模式启动实际 ShunCode，激活成功，版本为 0.7.9、默认只读，四个中文权限命令注册成功。

## 更正基线结论

最初 E 盘仓库与 D 盘发行包的三份运行产物 SHA-256 不同。逐文本核对后确认 `extension.js`、`agent-host.js`、`mcp-server.js` 的逻辑文本一致，差异来自换行格式。已固定 LF 规范并保留基线，不能把这次字节哈希差异误报为尚未回仓库的功能修复。

## 明确未完成的范围

- **完整源码重建尚未实现。** 仓库仍缺少 27 个引用的共享模块，以及完整工作台定制与运行时源码；上游公开 GitHub 内容接口本次返回 404，无法取得缺失部分。不能凭预编译基线“补齐”而冒充原始源码。
- **没有新增操作系统级终端沙箱。** 项目模式禁用任意终端和自定义命令；用户明确授予整机权限后，其能力仍受 Windows 账号而非工作区边界限制。
- 真正的授权确认按钮交互、全部原生 Chat/多模型模型接入和公网隧道故障恢复，未完成全量人工 GUI 回归。测试不把 IDE 适配器替身当作完整真实终端运行验收。
- 不自动重载用户当前编辑器，不断开当前维护 Bridge。运行中的旧扩展须在用户重载后才切换到新版本。
- 当前报告不宣称新的稳定版已发布；新稳定 Release 必须在剩余验收完成后创建。
