# MCP 安全边界

## 当前实现

所有远程工具的实际执行统一经过 `extension/src/bridge-security.js` 安装的调度检查，检查位于并发队列之后，因此排队期间撤销权限也会阻止后续执行。默认只读工具名单显式列出，未知工具和不明确的兼容别名失败关闭；自定义工具仅允许通过独立的整机会话授权运行。

新会话不继承旧会话权限。提升授权只存在内存中，默认 15 分钟，闲置过期 15 分钟；定时器和每次调用均检查过期。撤销时中止正在执行的非只读工具信号并请求释放会话所属终端命令。进程是否已经产生外部副作用无法撤回。

文件路径检查使用 `realpath` 验证已存在的父目录，包含新增文件、补丁移动目的地及显式诊断路径。仍需考虑检查与实际 I/O 之间的竞态：本实现不是内核沙箱，也不是对恶意本地进程同时更换链接的绝对防护。

`tools/list` 按会话过滤，权限敏感工具列表不允许公共缓存。远程调用参数不能授予权限；本机命令必须进行交互确认。现代无状态客户端使用协议既有的稳定 owner 范围，不能把自报客户端标识当作经过验证的个人身份。

## 日志与状态

审计记录仅保存时间、摘要会话 ID、动作和工具名，不保存工具参数或完整输出。Bridge 输出和活动展示对常见凭证模式脱敏；权限快照不暴露内部 owner 值。工具返回的文件内容和终端输出没有强制替换，避免悄悄修改实际数据，因此日志脱敏不意味着所有返回内容都没有秘密。

## 不覆盖的边界

- 整机终端、自定义工具本质上允许本机代码执行，不宣称工作区隔离。
- 只读文件可能包含凭证。用户负责选择适合开放的工作区。
- Native Chat 的工具权限不由本轮远程 Bridge 权限模块控制。
- 已授权命令可向网络发送数据；单靠 URL token 不能限制数据外发。
- 状态栏和命令面板需要真实编辑器 GUI 验收，不能用模拟 VS Code API 的测试替代。

## 下一阶段

需要完整工作区终端能力时，应使用专用受限账号、容器或虚拟机，明确文件挂载和网络策略；不得把 `cwd` 限制或 shell 字符串过滤宣传为沙箱。补齐共享源码后，应将目前的受校验增量挂接迁移为直接编译的调度器实现。

发现泄露时：停止 Bridge、轮换端点、撤销会话授权，并针对可能已读取的具体凭证进行轮换。仓库 Private 与本机 MCP 权限无关。
